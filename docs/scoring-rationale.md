# 判分粒度设计说明（scoring rationale）

本文档面向质检审阅，说明判分结构、难度轴设计与 verifier 真值计算方法。
筛选模型不可见本文档。

## 1. 判分结构：3 项 × 1/3

平台难度门要求"筛选模型得分 ≤ 0.700"。在 k 项等权二元判分下，任一单项失败
即 ≤0.700 的约束要求 1 - 1/k ≤ 0.700，即 k ≤ 3。因此 3 项二元是满足难度门的
唯一等权解；连续计分与难度门方向相反（部分达标即可越过 0.700），不采用。

| 项 | 内容 | 失败即 0 的典型原因 |
|---|---|---|
| ITEM 1 | HTTP 协议、端点与运行身份（端口归属 / venv / 遗留进程清理） | 未清理占位进程、未以 ledgersvc + venv 运行 |
| ITEM 2 | 重放正确性（基线真值 + 写入中事务块 + 追加/放弃/重试/墓碑/非法行闭环）+ 首次请求 20s 门槛 | 语义实现错误、把未提交事务计入统计、全量重放超时 |
| ITEM 3 | 增量 SLA + 压缩重写 + 20 并发 + flock 快照回退 | 每请求全量重放、并发重复累加、长持锁阻塞 |

## 2. 难度轴设计

本题难度来自两条相互独立的轴，与"规范实现类"题目（题面给出完备规范、
忠实实现即可满分）区分：

1. **信息挖掘轴（先验弱）**：journal 重放语义由 `samples/` 样本逐条标注自证；
   闭环表覆盖输入异常，但"写入中事务块（BEGIN 与数据已落盘、COMMIT 未落盘）
   是否计入统计"不由任何文档定义，只能由实现者对不变式的理解决定。题面的
   盘点锚点为模糊量级（"约 800 万条"），两种口径的差值（137 条）落在同一档内，
   无法用于消歧。
2. **物理性能轴**：基线约 950 万行 / 约 600 MB，单核 stdlib 全量重放实测 23.9 秒。
   首次请求 20s 门槛要求优化解析路径（镜像内 apt 渠道提供 ujson，属于"机器上
   现成工具"，题面不提示）；1.5s 增量门槛使"每请求全量重放"必然不合规，
   必须实现 tail-follow 增量状态。

实现面宽度（全部由闭环表/契约定义，属确定性工作量）：事务缓冲与提交、放弃
事务丢弃、紧邻重试去重、DEL 墓碑（含不存在的 key）、meta 子对象隔离、CKPT
基线重置、inode 变化检测与重建、flock 等锁上限与快照回退、20 并发单飞。

## 3. Verifier 真值计算方法

- **基线（2a）**：对当前文件做一次全量重放（流式分块，内存 O(状态)），与
  服务响应精确比对（全整数字段，无浮点容差——记账 delta 全为整数，杜绝
  NaN/浮点累积类绕过）。
- **运行期变更（2b-3d）**：verifier 维护独立的增量重放状态机，只解析新增
  字节；与服务的实现相互独立。
- **压缩重写（3b/3e）**：压缩后文件大幅缩短，verifier 对新文件全量重放。
- 写入端所有修改（追加/放弃/重试/长持锁/压缩）均持排他锁并 fsync，与题面
  写入端契约一致。

首次请求 20s 门槛的强制点：verifier 预热请求耗时落盘，ITEM2 2a 校验
elapsed ≤ 20s；全量重放超时的实现（未做解析优化）在该项被确定性淘汰。

## 4. 与题面的一致性边界

- 判分脚本不引入 instruction.md 之外的判定标准；时延门槛与宽限全部以题面
  为准（1.5s / 24s / 30s / 2s）。
- 闭环表中每一行都在评测或基线数据中实际发生；未列出的输入形态不出现。
- 紧邻重复行的去重口径（"与上一条已接受行 seq 相同则丢弃后一行"）在闭环表
  中显式定义，verifier 与参考解按同一口径实现。
