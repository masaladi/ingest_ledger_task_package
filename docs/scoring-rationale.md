# 判分粒度设计说明（scoring rationale）

本文档面向质检审阅，说明判分结构、难度轴设计与 verifier 真值计算方法。
筛选模型不可见本文档。

## 1. 判分结构：3 项 × 1/3

平台难度门要求"筛选模型得分 ≤ 0.700"。在 k 项等权二元判分下，任一单项失败
即 ≤0.700 的约束要求 1 - 1/k ≤ 0.700，即 k ≤ 3。因此 3 项二元是满足难度门的
唯一等权解；连续计分与难度门方向相反（部分达标即可越过 0.700），不采用。

| 项 | 内容 | 失败即 0 的典型原因 |
|---|---|---|
| ITEM 1 | HTTP 协议、端点与运行身份（端口归属 / venv / 遗留进程清理） | 未清理占位进程、未以 ledgersvc + venv 运行 |
| ITEM 2 | 重放正确性（基线真值 + 写入中事务块 + 追加/放弃/重试/墓碑/非法行闭环）+ 首次请求 20s 门槛 | 语义实现错误、把未提交事务计入统计、全量重放超时 |
| ITEM 3 | 增量 SLA + 压缩重写 + 20 并发 + flock 快照回退 | 每请求全量重放、并发重复累加、长持锁阻塞 |

## 2. 难度轴设计

本题难度来自两条相互独立的轴，与"规范实现类"题目（题面给出完备规范、
忠实实现即可满分）区分：

1. **信息挖掘轴（先验弱）**：journal 重放语义不由题面正文定义，题面明确
   `samples/` 下的样本与其逐条语义标注是**唯一的语义依据**，实现者必须通读
   样本并把标注口径落实为重放状态机。闭环表覆盖输入异常形态；两处易错口径
   均有显式定义载体，但都不在正文散文中，必须主动核对样本与闭环表才能拿到：
   - 写入中事务块（BEGIN 与数据已落盘、COMMIT 未落盘）不计入统计——闭环表
     显式定义；
   - 无效果 `DEL`（作用于当前不在账本中的 key）不计入 `records`——样本标注
     显式定义（样本 seq 33-35 的无效果墓碑演示行及逐条标注）。
   题面的盘点锚点为模糊量级（"约 800 万条"），两种读法的差值（基线 37 条）
   落在同一档内，仅凭量级锚点无法消歧。
2. **物理性能轴**：基线约 950 万行 / 约 600 MB，单核 stdlib 全量重放实测 23.9 秒。
   首次请求 20s 门槛要求优化解析路径（镜像内 apt 渠道提供 ujson，属于"机器上
   现成工具"，题面不提示）；1.5s 增量门槛使"每请求全量重放"必然不合规，
   必须实现 tail-follow 增量状态。

实现面宽度（全部由闭环表/契约定义，属确定性工作量）：事务缓冲与提交、放弃
事务丢弃、紧邻重试去重、DEL 墓碑（含不存在的 key；墓碑行的计数口径见上）、meta 子对象隔离、CKPT
基线重置、inode 变化检测与重建、flock 等锁上限与快照回退、20 并发单飞。

## 3. Verifier 真值计算方法

- **基线（2a）**：对当前文件做一次全量重放（流式分块，内存 O(状态)），与
  服务响应精确比对（全整数字段，无浮点容差——记账 delta 全为整数，杜绝
  NaN/浮点累积类绕过）。
- **运行期变更（2b-3d）**：verifier 维护独立的增量重放状态机，只解析新增
  字节；与服务的实现相互独立。
- **压缩重写（3b/3e）**：压缩后文件大幅缩短，verifier 对新文件全量重放。
- 写入端所有修改（追加/放弃/重试/长持锁/压缩）均持排他锁并 fsync，与题面
  写入端契约一致。

首次请求 20s 门槛的强制点：verifier 预热请求耗时落盘，ITEM2 2a 校验
elapsed ≤ 20s；全量重放超时的实现（未做解析优化）在该项被确定性淘汰。

## 3b. 防篡改真值基线

verifier 的真值与考生可写的 live journal 解耦，切断"被修改的文件同时充当
仿真与真值"的环形引用：

- **构建期冻结**：镜像构建时即生成只读基线副本
  `/opt/ingest-ledger/.journal.pristine` 与 SHA-256 摘要（`.journal.sha256`）。
  基线随镜像层存在，不依赖运行期 entrypoint——评测环境可能以自定义命令覆盖
  容器启动，运行期冻结在该场景下不会发生。
- **烧录摘要**：journal 摘要同时以常量形式烧录进判分脚本（gen_journal 固定
  种子，跨平台构建一致），基线文件与摘要即使被同时改写也会与烧录值冲突。
- **影子真值流**：verifier 启动时校验基线摘要（文件摘要与烧录常量双重），
  再复制为**本次评测专属的随机路径**影子真值流（路径每次评测由评测入口随机
  生成、权限 0600，考生无法预知路径预置伪造文件）；此后评测端所有追加
  （含长持锁直写）同步写入影子流，真值只重放影子流。校验通过后基线文件本身
  不再被读取，verifier 对固定路径无持久依赖。
- **压缩重写**只作用于 live journal；真值是完整历史的独立重放，与压缩形态
  在语义上必须等价——该等价性正是对应测试项校验的不变式。
- **失败分级（无降级）**：基线文件与摘要同时被改写、仅存其一、或基线整体
  缺失 → 一律评测硬失败（防篡改红线）。真值永不回退到考生可写的 live
  journal，不存在"摘要不符还继续评测"或"改写数据文件同时充当仿真与真值"
  的通道。

## 4. 与题面的一致性边界

- 判分脚本不引入 instruction.md 之外的判定标准；时延门槛与宽限全部以题面
  为准（1.5s / 20s / 30s / 2s）。
- 闭环表中每一行都在评测或基线数据中实际发生；未列出的输入形态不出现。
- 紧邻重复行的去重口径（"与上一条已接受行 seq 相同则丢弃后一行"）在闭环表
  中显式定义，verifier 与参考解按同一口径实现。

### 4.1 无效果 DEL 的计数口径说明

题面正文对该边界情形不作文字规定，但口径**有显式定义载体**：题面指定
`samples/` 下的样本与逐条语义标注是唯一语义依据，样本 seq 33-35 的无效果
墓碑演示行及标注明确规定——作用于当前不在账本中的 key 的 `DEL` 行合法、被
正常消费，但不改变账本、不计入 `records`，该 key 的 `last_seq` 也不更新。
因此判分脚本对该口径的执行不排斥任何题面允许的实现：与样本标注相悖的计数
读法本身不成立。设计意图：口径必须通过主动核对样本获得（正文与闭环表均不
含该口径），区分实现者是否真正把"样本是唯一语义依据"落实为重放状态机，而
不是凭先验假设实现。评分一致性约束：verifier 与参考服务对同一口径实现，并
对所有提交一致执行；该口径在评测中实际发生（2g2 无效果墓碑测试，含已被
墓碑移除与从未存在两类 key）。其余全部语义（事务边界、写入中事务块、ABORT
丢弃、重试去重、DEL 墓碑生效、非法行过滤、CKPT 重置、meta 隔离、缺失 delta
按 0 计入）均由闭环表与样本显式定义，且在评测中均有对应断言。
